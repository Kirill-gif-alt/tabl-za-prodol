# Модель «спрос от цены» для RMS КРАСАВИА — итог работы команды

Команда: аналитик данных, эконометрист по спросу, специалист по unconstraining, специалист по RM-оптимизации,
ML-инженер, критик. Каждый писал свой модуль на ваших данных. Критик пересчитал ключевые числа
и оспорил выводы. Ниже — решения, которые выдержали спор.

Данные: снимок сайта — 31 659 билетов с тарифом и кодом тарифа на момент покупки.
Продажи 06.02–07.10.2026, вылеты 23.09.2026–26.03.2027. Плюс история 13 418 вылетов (SalesHistory.csv) без цен по дням.
Персональных данных в расчёте нет.

**Главный вывод.** Цена уже влияет на спрос в нужную сторону: дороже — меньше бронирований. Но по имеющимся данным силу
этого влияния нельзя измерить достаточно точно, чтобы автоматически выбирать цену. Поэтому:

1. текущий прогноз загрузки остаётся основным;
2. новая модель с ценой подключается как поправка на ближнем горизонте;
3. оптимизатор работает как советник в узком коридоре;
4. параллельно запускаем сбор данных, которые дадут настоящую эластичность (раздел 6).

## 1. Подходы к учёту цены в авиационных RMS

| Подход | Суть | Плюсы | Минусы для вас (46/72/120, мало вылетов) |
|---|---|---|---|
| **Независимый спрос по классам + EMSR-b** (классика 1990-х) | Прогноз спроса на каждый класс, защита мест под дорогие классы | Просто, понятно | Предполагает, что пассажир не уходит в дешёвый класс. Цены у вас — лестница, и покупают самый дешёвый открытый. На ваших данных EMSR-b недобирал загрузку на 10–20 п.п. |
| **Q-forecasting / hybrid forecasting** (PODS, Belobaba) | Спрос считается «в пересчёте на самый дешёвый класс» и масштабируется по эластичности; «приоритетный» спрос отдельно | Учитывает buy-down, стандарт в современных RMS | Нужна эластичность (FRAT5) — у вас её пока не измерить точно |
| **Модель выбора MNL** | Вероятность купить класс j при открытом наборе S | Самая правильная для смеси классов | Нужна история открытых классов и много данных |
| **Dynamic pricing (DP по цене)** | Спрос λ(p,t) → цена (минимальный открытый класс) по дням и свободным креслам | При «покупают самый дешёвый открытый» это то же, что управление закрытием классов; точно решается для малых ВС | Качество полностью зависит от λ(p,t), то есть от эластичности |
| **ML-прогноз с ценой как признаком** (бустинг, байесовские модели) | Прогноз бронирований от цены, дней до вылета, сезона, направления | Дообучается, учитывает много факторов | Без вариации цены и данных инвентаря учит корреляцию, а не причинность: цену поднимали, когда спрос был высоким |

**Решение команды.** Действие — «открыт минимальный класс k» (это и есть цена).
Оптимизация — DP по дням и свободным креслам с bid price. Спрос — ML-модель на ближнем горизонте плюс параметрическая
эластичность по сценариям, пока не будет измерена. EMSR-b не используем.

## 2. Какие данные нужны и что делать, если их нет

| Данные | Есть? | Что делать |
|---|---|---|
| Цена и код тарифа на момент покупки, дата брони, дата вылета | **Есть** в снимке, но только с 06.02.2026. По прошлым годам — только средний тариф вылета | Выгрузить историю по билетам скриптом **Export-SalesTickets.ps1** за 2025–2026. Это главный рычаг: даст год дневных цен и полные кривые |
| Ёмкость (AU) и кресла в продаже на вылет | Есть только по текущим вылетам. В истории нет, а у 38% вылетов ёмкость отличается от обычной для рейса | Сохранять файл «загрузка таб» ежедневно (сайт уже публикует снимок) или выгрузить AU по датам из системы бронирования |
| **Открытые/закрытые классы по дням** | **Нет** | Самое важное для эластичности. Делать ежедневный снимок наличия мест по классам (AVS/инвентарь). Пока его нет, закрытие выводится из продаж: «продавали только дороже обычного» — это приблизительно |
| Возвраты по билету | Только в истории (сводно) | Есть в Export-SalesTickets.ps1 (REFUND_DTD) |
| Группы | Определяются по PNR (≥10) | Учитывать отдельно, это не ценовой спрос |
| Конкуренты (S7 на Горно-Алтайске и др.) | Нет | Минимум — даты входа и выхода конкурента и его тариф раз в неделю; можно вручную в календаре событий сайта |
| Потолки субсидированных тарифов | На сайте есть («Справочник» → «Тарифы субсидии», `shared/subsidy-fares.json`), в моей копии нет | Модель читает их сама. Без файла принимает преобладающий тариф рейса за потолок и пишет предупреждение |

Тарифы 0 ₽ исключены из спроса по цене, но считаются занятыми местами. Это 15% билетов, из них 91% — WOW на чартерах KV-9xxx.
Детские (/CN50 = 50%, /CN20 = 80%) тоже исключены.

## 3. Архитектура

```
данные (билеты с ценой, вылеты, история, потолки)            data_prep.py, common.py, scope.py
   │
   ├─ где RMS выбирает цену: межрегиональные + Богучаны, Мотыгино, Кодинск; потолок субсидии     scope.py
   ├─ восстановление спроса (распроданные рейсы, дни после распродажи)                         unconstrain.py
   │
   ├─ прогноз бронирований в день  λ(p, t | дни до вылета, неделя, день недели, направление,
   │     ёмкость, сколько уже продано)  — LightGBM (Пуассон), спрос монотонно убывает с ценой     model.py
   ├─ эластичность β по горизонтам (сценарии, пока не измерена точно)                           elasticity.py
   │
   └─ выбор класса:  V_t(x) = max_k E[ p_k·N + V_{t−1}(x − N) ],  N ~ продажи за день при цене p_k
         выход: «сегодня открыть класс X (цена Y ₽), закрыть всё дешевле» + bid price
         ограничения: лестница направления, потолок субсидии, не чаще раза в день     optimize.py
```

Формулы:
- **Спрос от цены:** λ(p,t) = a(t) · exp(β_h · (p/p_ref − 1)), где a(t) — кривая бронирований направления,
  β_h — эластичность на горизонте h (22+ / 8–21 / 0–7 дней).
- **Прогноз загрузки при цене p:** продано сейчас + Σ_{t<сейчас} λ(p_t, t), но не больше кресел.
- **Bid price:** b_t(x) = V_{t−1}(x) − V_{t−1}(x−1) — минимальная цена, по которой стоит продать ещё одно место
  (в том числе группе).

| `elasticity.py` | Пуассоновская регрессия с фиксированными эффектами вылета, β по горизонтам, сжатие групп (эмпирический Байес) | `PM_DATA=data python3 elasticity.py` |

## 5. Сравнение с текущей моделью

**Прогноз загрузки к вылету.** Бэктест: 8 срезов с шагом 7 дней (16.08–04.10), обучение только на продажах до среза,
307 пар «вылет × срез» (74 вылета). Средняя ошибка, пасс.:

| Модель | 1–3 дня до вылета | 4–7 | 8–14 | 15–30 | Все | Смещение |
|---|---|---|---|---|---|---|
| Новая (LightGBM, цена в признаках) | **2,6** | **6,1** | 7,5 | 10,6 | 8,3 | −6,9 |
| Текущая (файл ожидаемой) | 8,0 | 6,7 | 7,4 | **7,3** | **7,3** | +1,6 |
| Текущая + уже продано | 3,2 | 6,3 | 8,1 | 8,1 | **7,3** | +2,7 |

- **Бронирования за неделю вперёд:** новая модель точнее (2,00 против 2,29 пасс., лучше на 7 срезах из 8).
- **Вердикт критика (бутстрап по вылетам).** Разница в загрузке к вылету — ничья: +0,9 пасс., 95% ДИ [−0,8; +2,9].
  Новая модель лучше за 1–7 дней, хуже за 15–30 и занижает дальний горизонт. Причина — кривые истории обрезаны,
  а полных кривых с ценами в данных нет.

**Эластичность** (пуассоновская модель с фиксированными эффектами вылета, ДИ 95%):
- за 22+ дня: −0,12 [−0,31; 0,07]
- за 8–21 день: −0,36 [−0,57; −0,15]
- за 0–7 дней: −0,22 [−0,49; 0,06]

Знак правильный, но это **нижняя граница по модулю**. Цену поднимали, когда спрос был высоким, и без истории классов цена дня
известна неточно. Профиль «дальний горизонт эластичнее» данные пока не подтвердили.

**Выручка.** Честно посчитать, сколько выручки дала бы другая цена на исторических рейсах, **нельзя**: неизвестно, какие классы
были открыты. Модельный расчёт на 30 направлениях (оптимизатор против одной цены на весь период, в той же модели спроса):

| β (допущение) | DP против одной цены | DP против EMSR-b |
|---|---|---|
| −1 | +0,3% | +3% |
| −2 | +2,3% | +10% |
| −3 | +3,8% | +14% |
| −4 | +4,8% | +14% |

При измеренных β ≈ −0,25 оптимизатор открывает только верхний класс. Это артефакт заниженной эластичности.
Поэтому эти проценты — сценарии, а не обещание. Критик настоял, чтобы так и было написано.

**Что доказано:**
- цена влияет на спрос в правильную сторону;
- новая модель лучше на 1–7 дней и в прогнозе бронирований на неделю;
- DP и bid price считаются корректно, с потолками субсидии и лестницей.

**Что не доказано:**
- что новая модель лучше по загрузке к вылету в целом;
- конкретный прирост выручки.

## 6. План внедрения

**Быстрый выигрыш (1–2 недели):**
1. Запустить **Export-SalesTickets.ps1** за 2025–2026 и пересчитать всё (`data_prep.py --tickets-hist`).
   Ожидаем: год дневных цен и полные кривые. Это должно убрать занижение на дальнем горизонте и сузить ДИ эластичности.
2. Начать сохранять **ежедневный снимок наличия мест по классам** (хотя бы минимальный открытый класс по каждому вылету).
   Через 2–3 месяца это даст настоящую эластичность.
3. На горизонте ≤ 7 дней показывать в RMS поправку новой модели к текущему прогнозу.
   Здесь она доказанно точнее: 2,6 против 3,2–8,0 пасс.

**Затем (1–3 месяца):**

4. **Ценовой эксперимент:** на 2–3 направлениях (например ABA, KYZ, TOF) часть вылетов держать на ±1 классе от обычного.
   Решение о классе — случайное и записанное. Это единственный способ получить эластичность без смещения.
5. **Оптимизатор как советник:**
   - коридор ±1 класс от текущего;
   - потолок субсидии из справочника сайта;
   - запрет рекомендаций, снижающих прогнозную загрузку ниже порога;
   - bid price — для групповых запросов.

   Сравнивать решения с журналом решений сайта: там уже считается итог по выручке.
6. Перейти на Q-forecasting/hybrid, когда будет β по горизонтам и направлениям с ДИ ±0,3.
   Тогда снимать коридор и автоматизировать.

**Перед следующим отчётом** (замечания критика, приняты командой):
- прогнать все модули на одной версии `common.py` (направления Красноярска KJA/KCY уже объединены);
- в истории не подставлять средний тариф вылета вместо цены дня;
- брать ёмкость на дату вылета, а не обычную для рейса;
- в спросе по цене считать только взрослые платные билеты, без групп.
